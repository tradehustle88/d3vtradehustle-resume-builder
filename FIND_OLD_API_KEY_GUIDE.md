## 📍 Step-by-Step: Finding the Key

### 1. Open GCP Credentials Page

```powershell
npm run open:gcp-creds
```

Or visit: https://console.cloud.google.com/apis/credentials?project=tradehustleresumebuilder

### 2. Look for API Keys Section

You should see a section labeled **"API Keys"** with a table showing:
- **Name** (e.g., "Browser key (auto created by Firebase)")
- **Key** (partially hidden, e.g., `AIzaSyC...v6-_fM`)
- **Created** (date created)
- **Last used** (when it was last accessed)

### 3. Identify Keys by Partial Match

API keys are displayed with only the **first few characters visible**:

**Old key starts with:** `AIzaSyD-nOO`
**New key starts with:** `AIzaSyCFCN9`

Look for entries that start with these characters.

### 4. Click Each Key to View Details

Click on the key name or the key string to open the details panel. This will show:
- Full key restrictions
- Usage metrics
- Creation date
- Last modified date

## 🎓 Understanding Firebase API Keys

**Important:** Firebase Web API keys are meant to be public!

They're safe to use in client-side code because:
- ✅ They identify your Firebase project
- ✅ Security is enforced by Firebase Security Rules
- ✅ Domain restrictions prevent unauthorized use
- ✅ They're not the same as service account keys

**However**, exposing them in git history is still bad practice because:
- ⚠️ Makes it easier for attackers to target your project
- ⚠️ Can be used to send requests to your Firebase project
- ⚠️ Increases risk if security rules are misconfigured
